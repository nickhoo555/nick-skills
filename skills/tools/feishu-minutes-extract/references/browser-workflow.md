# 浏览器采集流程

## 网络 / HAR 路线（Agent 默认）

1. 绑定用户给出的浏览器标签页，确认标题和 `/minutes/<token>` URL。保留现有登录态；无查看权限时停止。
2. 使用已提供的网络检查能力。如果没有网络工具但可操作 Chrome 原生界面，打开 DevTools → Network。开启录制后刷新当前妙记一次；点击「文字记录」确认其能显示。页面若有正在编辑的未保存内容，先避免刷新并请用户处理。
3. 过滤到 `<实际租户>.feishu.cn/minutes/`；观察 `subtitles/paragraph-ids`、`speakers` 和 `subtitles_v2`。导出 **HAR（已清理）** 到工作目录。这里的「已清理」主要去掉 Cookie 等认证头，不代表已去掉会议内容。无需开启带敏感数据的 HAR 导出。
4. 离线运行 CLI，并检查 manifest。导出器仅保留三个白名单端点，HTML、权限检查、视频、遥测和其他会议都被排除。不要将整份 HAR 放进可复用 Skill 或上传外部服务。
5. 如正文没有覆盖全部索引，返回「文字记录」滚动使页面继续加载，或请用户使用下方浏览器采集器重新取完整数据。再次捕获应使用新的文件，避免混入编辑前后两个版本。补齐后重跑到新的输出目录。
6. 关闭本次打开的 DevTools，并尽量恢复用户原来的文字记录视图。验证结果来自输出 manifest，不靠截取页面上几段文字推断成功。

只有 DOM evaluation 的工具不能用于网络抓取。该路线不读取 React 私有状态、Cookie、本地存储、浏览器配置文件或本机调试端口。

## 用户自行执行浏览器采集器

提供本 Skill 中完整的 `scripts/browser-export.js` 文件，让用户先检查代码，再在有查看权限的妙记详情页的 DevTools Console 中执行。

- 脚本只访问同源三个文字记录端点，使用浏览器已有会话；不读取、导出或保存 Cookie。
- 默认每批 100 段，依次请求；30 秒单次超时，索引最多 100 页；不自动重试。
- 源语言 `translate_lang=default`，非流畅润色 `is_fluent=false`，保留网页观察到的 `filter_speaker=true`。
- 完成后下载 `<token>.capture.json`，里面是每个响应的原始正文字符串。用 CLI 生成原始文件和全文，CLI 会再次校验完整性。
- 采集失败只打印错误，不生成看似成功的残缺下载。HTTP/业务/结构错误时停止，改查 Network；不修改权限或安全设置。如浏览器拒绝粘贴，改走 HAR，不指示关闭安全保护。

浏览器版本/租户若更改协议，先实测维护适配器。采集器的分页与小批量行为有合成测试和真实响应回放测试；当前真实网页证据是一页索引、一次 117 段正文响应，不能把这一点泛化为所有租户已经实测。
