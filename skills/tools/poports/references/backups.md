# 分层备份与恢复

## 默认保留策略

各层的时间窗口互斥，以备份文件名中的 UTC 时间计算。时间段内只保留最新的一份，最近 7 天除外。

| 备份年龄 | 保留粒度 |
| --- | --- |
| 不足 7 天 | 全部保留，含同一天多次手动备份 |
| 7 天至不足 30 天 | 每个 UTC 自然日 1 份 |
| 30 天至不足 12 周 | 每个 ISO 自然周 1 份 |
| 超出上述范围，月份差不足 24 个月 | 每个自然月 1 份 |
| 月份差达到 24 个月及更早 | 每个自然年 1 份，长期保留 |

边界按该次执行时间计算；ISO 周同时包含 ISO 周年，跨年不会误合并。时钟回拨时，未来时间的文件全部保护，不阻止当天生成新备份。稀疏历史保留实际存在的关键点，不伪造缺失年月的快照。

## 托管备份与独立备份

- `backup` 不带文件名时，默认写入 `<数据库完整路径>.backups/`。`--backup-dir /absolute/path` 可覆盖目录；定时与手动执行应使用相同目录。
- 文件名包含数据库规范绝对路径的哈希、UTC 时间和随机 ID。只清理当前数据库命名空间中符合完整格式的普通文件；其他数据库备份、非法文件名、目录和软链保持不变。数据库移动后旧路径命名空间不再自动清理，应明确审核后单独处理。
- `backup /absolute/path/important.sqlite3` 是独立备份，不参与自动淘汰；适合永久保护升级前或重大变更前的恢复点。不要手工仿造托管文件名。
- 显式文件名不能组合 `--if-due` 或 `--backup-dir`。每日幂等与自动淘汰仅针对托管备份。

## 写入与删除安全

SQLite backup API 产生一致性快照，完成完整性检查后才原子发布，再执行淘汰；备份失败不删除旧文件。`backup-prune` 默认只预览，`--apply` 才执行，并先验证最新恢复点。清理发现目录被外部修改时停止；不要同时用其他程序编辑该目录。

同一数据库、同一目录的备份与淘汰由文件锁串行化；多个每日任务同时触发也只产生当天一份快照。`--if-due` 按执行机器的本地日期判断是否已完成当天备份，与本地每日调度对齐；存储时间和淘汰分组仍使用 UTC。当天最新备份损坏则报错而非默默跳过，可排查后运行不带 `--if-due` 的手动备份。

新备份文件权限为 `0600`，新目录为 `0700`。备份可能含备注中的凭据，按台账相同等级保护。仅在同一磁盘保留副本不能防止磁盘损坏；需要异盘保护时显式选择本机挂载的备份盘目录，避免多机共享写入。

## 恢复

先暂停调度及其他写入方。用 `poports --db /absolute/path/selected-backup.sqlite3 check` 检查候选快照，再复制到新的工作数据库路径并 `configure --db` 指向新文件；不要直接把正在参与淘汰的托管备份配置成工作库。检查记录与历史最高端口符合预期后，再恢复调度并更新其数据库路径。
